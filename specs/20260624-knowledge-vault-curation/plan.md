# Implementation Plan: Knowledge Vault Curation

**Branch**: `20260624-knowledge-vault-curation` | **Date**: 2026-06-14 | **Spec**: [spec.md](./spec.md)

## Summary

Close the session↔vault loop: App Home bifurcates Vault vs Sessions; Session Hub gains Upload to vault (batch LLM extraction + candidate screen) and Download session MD; vault schema extends with definitions, facetCoverage, and reviewItems; Review merges dual pools and routes vault answers to mastery + SM-2 + facetCoverage updates with decay calibration logging.

## Technical Context

**Language/Version**: JavaScript ES modules (browser PWA, no build step)

**Primary Dependencies**: Existing vault-store, mastery-model, session-store, project-store, api.js LLM, sm2.js, review.js, ui.js

**Storage**: localStorage (`pith_knowledge_vault`, `pith_knowledge_vault_data`, `mylearning_decay_calibration_log`)

**Testing**: `cursor-tests/*.mjs` Node ESM with jsdom where needed

**Target Platform**: Browser PWA (offline-capable)

**Project Type**: Single-page web application

**Performance Goals**: One LLM call per upload action; review queue build < 100ms for typical vault sizes

**Constraints**: English UI; PWA SW_VERSION bump on src changes; no localStorage wipe on migration

**Scale/Scope**: ~15 files touched; 2 new screens; 1 new module (`vault-curation.js`)
